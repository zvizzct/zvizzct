# Víctor Puerta

Full-stack developer in Barcelona. Most days I'm building internal tools, automation, or something with AI.

I build software end to end: interfaces, APIs, data systems, and the AI workflows that connect them. Most of my recent work is private — engineering operations, R&D, and tools that help teams move faster without losing clarity.

## Current focus

- Full-stack product work at **Eurecat**, across client and R&D projects.
- Agent tooling: MCP gateways, integrations, and conventions that make agents usable in a team.
- Data pipelines that extract, classify, enrich, and retrieve technical context.
- Local-first AI: speech-to-text, retrieval, and generation running on-device.
- Backend architecture for systems that need to stay understandable as they grow.

## Selected work

- **Agent Tooling** — a governed registry and internal MCP gateway: one `/mcp` endpoint that enforces the catalog, per-user grants, and credential delivery, and audits every call.
- **UES Catalog** — a GitLab-to-catalog pipeline enriched with LLMs, so repository knowledge is searchable instead of scattered.
- **Operational Memory** — a local-first system that gives agents durable memory: projects, tasks, and decisions that survive across sessions ([code](https://github.com/zvizzct/organizacion)).
- **BIA** — a local-first desktop app (macOS and Windows) for governance meetings: recording, transcription, retrieval, and drafting, with nothing leaving the machine.
- **Antes de La Odisea** — an interactive atlas of a video essay about The Odyssey, with the YouTube player as the narrative clock ([live](https://antes-de-la-odisea.vercel.app) · [code](https://github.com/zvizzct/antes-de-la-odisea)).
- **FocusGate** — a macOS menu-bar app for strict focus sessions over NextDNS; an active timer cannot be stopped early.
- **Closet Native** — a SwiftUI wardrobe app with AI vision, outfit generation, and a usage calendar ([code](https://github.com/zvizzct/outfit-ios)).

## How I work

My starting point is full-stack development: frontend, backend, APIs, data flows, and product work, especially when software has to solve a real problem. Alongside delivery, I usually improve how the work gets done — internal tools, documentation, automation, and shared conventions that save everyone time.

I'm interested in applied AI in the same practical way: I care less about novelty than about where it actually helps, where it needs limits, and how it becomes part of everyday engineering work.
